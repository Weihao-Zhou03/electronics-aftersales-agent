# 已知限制与未验证能力

这是虚构商家演示数据上的单机试用实现。`demo` 全程明确标识模拟订单、库存和履约，DemoProvider 不产生真实退款、仓库出库或承运商运单。公司 SSO/CRM/OMS/WMS、真实支付/物流和维修/跨SKU/分期/多币种等连接器未实现；`external` 明确失败，不模拟成功。

当前仍在持续验收，逐项状态见 acceptance 与 implementation-status。真实开发集调试失败、v1完整冻结结果和中止稳定性已保留。v1虽达到统计门槛，A06未真正移交仍阻断；已修复服务端强制移交，正在用完整开发集及独立新冻结v2重验。真实Widget、三演示整体、OS进程恢复、空卷安装与加密恢复已有实测报告。独立 ChatGPT 审查尚未发生。模型引用自动检查不能代替人工语义抽查。

本地 EasyCLIProxyAPI 是外部依赖，用户手动启动其核心和 Docker Desktop。订阅配额、模型名和上游可用性由网关决定；没有货币计价/上游完整usage时不填零成本。曾在并发模型评测/页面调用窗口出现30秒及60秒超时，HTTP失败会真实降级，报告保留；独占页面9/60通过，完整v2评测改为独占串行条件，不能推导代理高并发可用。应用没有代理的 OAuth token，仓库不包含任何个人模型凭据。协议兼容已经实际测试，但没有验证所有 OpenAI 兼容供应商。

Chatwoot community 4.19.0-ce 的 bot token 没有历史消息列表权限。运行时专用普通客服 token 仅用于该 GET；不使用管理员回退。升级需重新执行兼容性验收。客户历史页只返回实际API最近一页的公开消息；未实现更早页分页，页面明确标注。跨系统最后一次GET与消息POST无法共同事务，发送结果不明保持暂停，员工核对后显式恢复。

客户退出/切换会话会撤销当前聊天绑定，并使旧Agent任务/未确认草稿失效。已经确认并获员工授权的履约按业务义务继续；接管聊天不会撤销合法退款/出库任务。员工私有通知的发送结果不明也不自动重发，管理台显示不确定计数，应在Chatwoot核验；门户待办和case仍是权威。

未进行公网DNS/HTTPS终止、跨主机部署、多副本生产负载、真实企业权限审计或受控客户试用。资源快照与小规模并发测试不构成容量承诺。会话上下文有60,000字符预算，超限转门户/人工，不声称无限长记忆；单轮默认9模型/8工具、每客户每日150轮。

私有附件限5MB PNG/JPEG/WebP，实际解码校验格式/像素并做owner授权。当前本地文件卷存储，没有对象存储/杀毒/OCR/视频处理。HTTP multipart解析器可能在业务函数检查前使用临时磁盘；公网部署还需代理层请求体限制。默认PG/Redis不发布公网端口。

备份覆盖三个数据库、附件、Chatwoot storage和限定配置，默认暂停写入后加密；不含Redis未投递队列、主机/TLS配置或外部模型网关。恢复演练验证独立库及文件，不替换运行实例、不宣称零丢失。加密归档在内存处理，未验证大体量备份、异地存储、自动告警或RPO/RTO。

基础seed是小规模虚构输入，复用已有记录不重置；首次seed的时间随运行日生成，历史订单自然到期。重新演示使用独立场景seed生成新数据，不能删除已有办理记录来伪装重放。新增场景用户的密码继承本地demo模板hash，具体用户名由脚本输出，不是固定公司用户。
