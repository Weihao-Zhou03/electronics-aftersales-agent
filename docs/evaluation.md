## 失败与边界

- `dev-009` 实际询问“请先选定要退的那一笔”“您可以直接回复订单号”，未创建草稿；保守关键词评分没有识别“选定”。原始未完成标记保留，该开发者解释没有改分。
- `dev-018` 正确使用旧政策并完成资格核验，却没有创建预期草稿，仍是任务未完成。
- 首次 `holdout-008` 创建了正确的换货草稿，但在 6 次顺序工具调用后触达模型调用上限，最终只有上限提示，没有预览与条款说明，任务及引用均失败。
- 首次 `holdout-005` 创建草稿后，实际模型请求发生 `ReadTimeout`，调度器停止后续任务；没有正式申请、付款义务或库存预占越权增加。两个数据库 schema 均已清理。保留失败证据，不以调整提示词/预算消除冻结集失败。
- 完整重跑的 `holdout-006` 产生正确换货草稿，但触达 6 次调用上限，最终未展示预览及引用；`holdout-025` 只完成旧政策核验，未产生预期草稿；`holdout-028` 缺政策时正确停止办理并说明需人工核实，却没有实际调用转人工工具，控制状态仍为 `BOT_ACTIVE`。这三项保持未完成；最后一项说明“说需要人工”不能等同于完成接管。
- 正常退货/换货中的完整办理步骤由合法客户、员工以实际认证、CSRF、版本和幂等键调用 ASGI API；演示人工凭证用于最终结算。这些步骤不是模型自主批准、真实支付或真实物流。
- 政策引用自动检查包括实际检索依据、政策版本和条款标识匹配。开发者语义抽查见 [citation-check.md](citation-check.md)，不等于人类抽查或独立审查；人类抽查仍待进行。
- 冻结之前发现的问题与原失败报告保留于 [development-log.md](../evals/development-log.md)。没有对公平基线做实测，不宣称编排或检索方案有比较增益。

## 复现

先按 [verification.md](verification.md) 创建独立 `aftersales_test`、安装 vector 扩展并开放仅本机测试端口，在本地忽略配置中提供真实模型配置；不能指向实际业务库。未设置 `TEST_DATABASE_URL` 时，评测器使用 `.env` 的 `AFTERSALES_DB_PASSWORD` 构造 `127.0.0.1:15432/aftersales_test`，不会输出密码。每轮仅创建并清理带随机 UUID 的本轮 schema。

```powershell
uv run python scripts/evaluate.py --revision v2 --split dev --concurrency 1 --output docs/evidence/reproduced-dev-v2.json
uv run python scripts/evaluate.py --revision v2 --split holdout --concurrency 1 --output docs/evidence/reproduced-holdout-v2.json
uv run python scripts/evaluate.py --revision v2 --split stability --concurrency 1 --output docs/evidence/reproduced-stability-v2.json
```

v2 CLI 保留原来的 40 项 `dev-v1.json`，选择全新的 `holdout-v2.json`，使用 `freeze-v2.json` 和 `eval-*-v2-latest.json`；新数据集由未继承旧结果上下文的另一 Codex 子代理编写，禁止读取旧结果或调用模型，这不等于独立审查。模型、提示词与评分不变，预算调整在新冻结前明确记录；验收百分比和安全要求没有降低。以上 v2 结果均来自实际完整运行，没有由 v1 推导或拼接。

上述命令用于已经包含冻结记录的仓库，省略 `--freeze`，并将复验写入新文件，保留冻结清单引用的原始报告。只有维护者初次建立一个尚无冻结文件的新 revision 时，才在完整开发集满足门槛后运行一次 `--freeze <完整开发报告>`；现有 `freeze-v1.json` / `freeze-v2.json` 禁止覆盖。当前 CLI 仅注册 `v1` / `v2`，后续版本需要显式增加新数据集和选项，不能直接传入 `v3`。运行时的版本、哈希、并发与完整集合执行数量须一起报告。后续重跑保留集必须保留前次部分报告、说明重跑原因，不能挑选较好单项拼成一次运行。
